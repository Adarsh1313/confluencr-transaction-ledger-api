# Assumptions

Decisions the brief left open, and how this implementation resolves them. The reasoning behind each, with the alternatives considered, is in [docs/decisions.md](docs/decisions.md).

## Money

- **Amounts are integers in paise** (100 paise = ₹1). Integers avoid floating-point rounding errors. The brief's examples (100, 50, 30) work exactly as written.
- **INR only, with no currency field.** Walnut Folks Group is India-based. Confluencr runs campaigns in 15+ countries, so multi-currency is a likely next step: a `currency` column on accounts, rejecting or converting cross-currency transfers, and per-currency minor units.
- **Limits:** amount 1 to 10¹² paise (₹1,000 crore) per transaction. A balance cannot exceed 9,007,199,254,740,991 paise (JavaScript's exact-integer limit); a credit past it is rejected with `422 BALANCE_LIMIT_EXCEEDED`.

## Accounts

- **No authentication.** The brief doesn't mention users. In production every route would sit behind auth, and accounts would belong to users.
- **Name** is required, trimmed, 1–100 characters. Any other field in the request (including `balance`) is rejected with `400`.
- **IDs are generated by the server** with a type prefix: `acc_…`, `txn_…`, `trf_…`, `att_…`.

## Transactions

- **`description` is optional**, up to 255 characters. The brief lists it as a field but not as a required validation.
- **`reference_id` is scoped per account.** The same value can be used on different accounts.
- **A duplicate `reference_id` returns `409`** with the original transaction in `error.details.transaction`, even if the new amount differs, so the client can see what was actually recorded.
- **Only a successful transaction claims a `reference_id`.** A debit rejected for insufficient balance can be retried with the same `reference_id` after topping up.
- **Every transaction stores `balance_after`**, the running balance right after it, like a bank statement. It is not required by the brief, but it makes history self-explanatory.

## Rejected debits

- **Rejected debits are not transactions.** Like a bank's internal log versus its official statement, they are stored as *attempts* (`GET /accounts/:id/attempts`) for auditing. They never appear in history and never affect the balance.
- **Only business rejections are logged** (insufficient balance). Malformed requests (`400`) are not.

## History

- **Ordering:** newest first by `created_at`, ties broken by `id`, so pages never shuffle.
- **Pagination:** `page` defaults to 1, `limit` to 20 (max 100). Invalid values return `400 INVALID_PAGINATION`. A page past the end returns an empty list with correct totals.

## Transfers

- **A transfer is one transfer row plus a debit and a credit**, each tagged with `transfer_id`, written in one database transaction.
- **A transfer's `reference_id` is unique per source account.** The two halves use the internal reference `transfer:<transfer id>`, so client `reference_id`s may not start with `transfer:`.
- **Transfers to the same account are rejected** with `422 SAME_ACCOUNT_TRANSFER`.
